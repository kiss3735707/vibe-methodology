4. 若有「会话交接块」，优先按交接块恢复

## 工作协议（防上下文丢失）

1. **一次一个里程碑**：每个里程碑 = 实现 + 自动化验证 + 用户验收 + 记录 + 提交请示，全部完成才进入下一个
2. **Ready 才开工**：成功标准可测、验证命令已知、范围不跨两个系统。M0 必须先有一条可重复的验证命令
3. **验证优先**：纯逻辑用项目的 `{test_cmd}`；界面 / 手感由用户按验收清单确认。**禁止代勾用户验收**；自动化验证必须跑命令并记录输出摘要
4. **修 bug 先红后绿**：先写复现（红）→ 修 → 全绿 → 记录 → 提交请示；无复现的修复是猜测
5. **收尾必记录**：里程碑完成后立即更新本文件（状态 / 验证结果 / 决策 / 待调参）；**未记录 = 未完成**
6. **SSOT 自检**：更新后检查——状态表无重复/过期行、状态与「下一步行动」无矛盾、每条决策有有效标记
7. **上下文告警时**：先写「会话交接块」（当前状态 / 下一步精确动作 / 未决问题），再继续或结束
8. **外科手术**：只改本里程碑需要的文件；发现无关问题记入「已知问题」，不顺手重构
9. **提交先问**：未经用户明确同意不 `git commit` / `git reset --hard`
10. **中途改需求**：先停实现，更新成功标准（用户可见则改 DESIGN），再继续
